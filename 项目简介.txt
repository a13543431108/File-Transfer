--------------------------------------------------------------------------------
一、项目定位
--------------------------------------------------------------------------------

一个跨平台 P2P 文件互传系统，包含【电脑端（Python）】【安卓端（Kotlin）】
【信令服务器（Python）】三部分。两端协议完全兼容，既支持传统局域网直连，
又新增"公网房间模式"——通过一台低带宽信令服务器牵线，让处于不同网络（异地）
的设备也能像在同一房间一样互传文件。

核心特点：
  · 局域网模式：零配置，同一路由下自动发现、直接互传
  · 公网房间模式：输入相同房间号即可跨网络组网（服务器只牵线，不传文件）
  · 服务器零带宽负担：只交换几十字节的地址信令，文件全部两端直连
  · 复用成熟传输协议：断点续传 / zlib 压缩 / SHA-256 校验全部沿用

三、功能特性总览
--------------------------------------------------------------------------------

【基础传输能力】（局域网 + 房间模式共用）
  ✅ 单文件传输
  ✅ 文件夹递归传输（skip / full / resume 增量）
  ✅ 断点续传（单文件 + 文件夹，跨会话）
  ✅ 文本文件 zlib 压缩（22 种扩展名，level 6）
  ✅ SHA-256 完整性校验
  ✅ IPv4 / IPv6 双栈
  ✅ 多设备并发发送
  ✅ 动态缓冲区自适应（电脑 256KB~8MB；安卓 16KB~4MB）
  ✅ TCP KeepAlive 抗断线
  ✅ 来件确认弹窗、上线自动续传提醒
  ✅ 路径穿越防护

【局域网模式特有】
  ✅ UDP 广播发现（同网段秒发现，无需外网）
  ✅ 子网扫描（广播被禁时兜底）
  ✅ 心跳保活 + 超时清理

【公网房间模式（新增）】
  ✅ 输入房间号即组网，支持动态加入（完全开放，最多 16 人）
  ✅ 服务器只做"房间匹配 + 地址交换 + 打洞协调"，不转发任何文件数据
  ✅ TCP 打洞（TCP 同时打开），打通后复用现有 TCP 协议直连
  ✅ 一进房间即全连接（网状），成员状态实时可见
  ✅ 服务器启动显示局域网 IP + 公网 IP，获取失败不退出
  ✅ 信令服务器双栈（IPv4 + IPv6 同时监听）
  ✅ 客户端上报公网 IPv6，支持 IPv6 打洞直连（两端都有公网 IPv6 时）

--------------------------------------------------------------------------------
四、端口与协议对齐
--------------------------------------------------------------------------------

【局域网模式】
  UDP 9998   设备发现（心跳 / 广播 / 回复）
  UDP 9997   主动扫描探测（与收发隔离）
  TCP 9999   文件数据传输

【公网房间模式（信令服务器）】
  UDP 3336   信令交互（加入房间 / 心跳 / 打洞协调）
  TCP 3337   TCP 映射观测（客户端连此端口以暴露其 TCP 公网映射）

【IPv6 / 双栈】
  三端均支持 IPv6：
  · 信令服务器：UDP 3336 与 TCP 3337 同时监听 IPv4 + IPv6（双栈）
  · 客户端：上报 IPv4 内网地址 + 公网 IPv6（过滤 fe80:: 链路本地）
  · 地址格式：IPv6 用 [ip]:port（方括号区分端口），如 [240e::1]:3336
  · 打洞：内网地址优先，其次 TCP 公网映射（v4/v6 均支持）
  · 服务器地址栏支持四种填法：host / host:port / [ipv6]:port / 纯 IPv6

【两端二进制协议（大端序）】
  SHA-256   : 64 字节 hex
  压缩      : zlib level 6（22 种文本扩展名）
  续传状态  : .p2p_resume/resume_{role}_{ip}_{file}.json
  心跳阈值  : 3 次失败移除
  节点超时  : 600 秒
  重试退避  : 2/4/8 秒，最多 3 次

五、公网房间模式 · 工作原理
--------------------------------------------------------------------------------

  为什么需要它？
    局域网模式依赖"同一网段"，异地设备互相不可见。
    家宽虽有一个公网 IP，但绑在路由器上，内网服务器电脑无法被外网直接访问。
    公网房间模式用一台有公网 IP 的服务器做"牵线人"，让两端打洞直连。

  核心流程：
    ① 设备 → 服务器：注册房间号（服务器记录其公网地址）
    ② 服务器：当同房间出现 ≥2 台设备，把彼此地址互相下发
    ③ 两端：收到对方地址后，同时向对方发起 TCP 连接（打洞）
    ④ 打通：得到一条直连通道，之后传文件完全走两端直连
    ⑤ 服务器：全程只交换几十字节的地址信令，不碰任何文件数据

  服务器职责（严格单一）：
    · 房间匹配：相同房间号拉入同一房间
    · 成员管理：新成员加入广播、成员离开通知、心跳超时剔除
    · 打洞协调：下发统一打洞时刻 + 双方 TCP 公网映射
    · 零数据转发：不消耗文件带宽

  打洞原理（TCP 同时打开）：
    两端各自用同一个本地端口，同时向对方的公网映射发起 connect。
    NAT 各自为此建立映射，对方的 SYN 到达时认为"这是我们主动发过的目标"，
    放行 → 形成一条 TCP 连接。两端各持这条连接的一端，均可收发。

  失败与回退：
    · 对称 NAT / 运营商 CGNAT / 手机蜂窝网下，打洞可能失败（物理限制）
    · 失败时提示用户，不做中继（因服务器带宽小）
    · 建议优先 IPv6（无 NAT，直连）

六、使用方式
--------------------------------------------------------------------------------

【电脑端】
  1. 直接运行：python 文件互传.py（纯标准库，无需 pip）
  2. 局域网：点"自动搜索"发现设备，勾选后发送
  3. 房间模式：在"房间模式"面板填服务器地址 + 房间号，点"加入房间"
     · 服务器地址下拉框可选历史（最多 5 个，自动持久化）
     · 加入后房间成员显示在"在线设备"列表，带 [房间设备] 标识

【安卓端】
  1. Android Studio 打开 android/ 目录，编译安装
  2. 局域网：广播搜索 / 扫描子网
  3. 房间模式：展开"房间模式"卡片，填服务器地址 + 房间号加入

【信令服务器】
  1. 部署到有公网 IP 的机器（云服务器或自家宽带+端口转发）
  2. 运行：python 信令服务器.py
  3. 启动后显示局域网 IP 与公网 IP，把它填到客户端"服务器"栏
  4. 防火墙放行 UDP 3336 + TCP 3337

八、关键设计原则
--------------------------------------------------------------------------------

  1. 单一职责：服务器单文件；电脑端内联房间模块（Rm* 类，单文件可独立分发）；
     安卓端拆独立 room/ 包
  2. 单一来源：所有可调参数集中在文件顶部（电脑端 RM_* 常量 / 安卓端 RoomConfig.kt）
  3. 房间号才启用：不输入房间号 → 完全维持原局域网行为，服务器代码不触发
  4. 复用长连接：打洞得到的连接保持打开，发送时复用；接收由 listener 统一处理
  5. 最小侵入：新增房间模式叠加于原有局域网逻辑之上，不改动成熟传输协议
