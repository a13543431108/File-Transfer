# File-Transfer 文件互传

一个基于局域网的 P2P 文件互传项目，包含 **电脑端（Python）** 与 **安卓端（Kotlin + Jetpack Compose）** 两个客户端。两端协议完全兼容，可跨平台互传，支持**断点续传**、**IPv4/IPv6 双栈**、**多设备并发发送**、**文件夹递归传输**、**zlib 压缩**与 **SHA-256 完整性校验**。

---

## 📦 组成

| 端 | 目录 | 技术栈 | 说明 |
|---|---|---|---|
| 电脑端 | `电脑端/` | Python 3.7+（纯标准库） | Windows / Linux / macOS 桌面 GUI（tkinter） |
| 安卓端 | `android/` | Kotlin + Jetpack Compose | Android 7.0+（API 24+），前台服务保活 |

两端使用**完全相同的二进制协议**（大端序），可在同一 Wi-Fi 或异地组网（ZeroTier / Tailscale / WireGuard）下互通。

## 📡 端口说明

【局域网模式】

| 端口 | 协议 | 用途 |
|------|------|------|
| `9999` | TCP | 文件数据传输 |
| `9998` | UDP | 设备发现、广播、心跳 |
| `9997` | UDP | 主动扫描探测（与收发隔离，避免干扰传输） |

【公网房间模式】

| 端口 | 协议 | 用途 |
|------|------|------|
| `3336` | UDP | 信令交互（服务器，加入房间/心跳/打洞协调） |
| `3337` | TCP | TCP 映射观测（服务器，客户端连接以暴露 TCP 公网映射） |
| `3338` | UDP | NAT 类型探测（服务器，对称 NAT 检测用） |
| `9996` | UDP | UDP 打洞专用端口（客户端，与局域网 9998 隔离） |
| `9995` | TCP | 房间模式打洞/长连接端口（客户端，映射观测 + 打洞共用） |

> ⚠️ 局域网模式确保 `9997/9998/9999` 未被拦截；房间模式确保 `9995/9996` 放行；服务器确保 `3336/3337/3338` 放行。

## 🚀 电脑端（Python）

### 环境要求

- **Python 3.7+**（推荐 3.9+）
- 依赖：全部使用标准库，**无需 pip 安装任何第三方包**
  - `socket`、`struct`、`threading`、`hashlib`、`json`、`zlib`、`tkinter`、`ipaddress` 等
- 操作系统：Windows / Linux / macOS
  - Windows 上使用 `os.startfile` 打开接收目录
  - Linux/macOS 需要系统安装 `python3-tk`

> 若缺少 `tkinter`，请安装：
> - Ubuntu/Debian：`sudo apt install python3-tk`
> - CentOS/RHEL：`sudo yum install python3-tkinter`
> - macOS：`brew install python-tk`

### 快速开始

```bash
# 直接运行
python 文件互传.py

# 或 Windows 双击运行
```

### 使用流程

1. **启动程序**：自动获取本机 IP、开启广播、启动 TCP 监听（端口 `9999`）。
2. **发现设备**：
   - 点击「自动搜索」→ 广播探测，最快（推荐）
   - 点击「手动添加」→ 输入对方 IP（支持 IPv6）
   - 开启「后台扫描」→ 每 20 秒自动刷新设备列表
3. **选择接收方**：在左侧设备列表中**按住 Ctrl / Shift 多选**。
4. **添加发送内容**：右侧「添加文件」/「添加文件夹」，可上移下移排序。
5. **点击「极速发送」**：向所有选中设备并发发送。

## 📱 安卓端（Kotlin + Compose）

### 环境要求

- Android Studio Ladybug (2024.2) 或更高
- JDK 17 或 21（Android Studio 会自动下载）
- Android SDK 35
- Gradle 8.7（wrapper 已配置）

### 构建与运行

1. 使用 Android Studio 打开 `android/` 目录。
2. 等待 Gradle Sync 完成（首次会自动下载 JDK 和依赖）。
3. 连接 Android 7.0+（API 24）设备，直接点击 Run。
4. 首次启动会请求通知 / Wi-Fi 相关权限，请全部允许。
5. 建议在系统设置中允许应用“忽略电池优化”，以避免后台网络被系统杀死。

### 与电脑端联调

1. 手机与电脑连接同一 Wi-Fi（或同一 VPN 网络如 ZeroTier / Tailscale）。
2. 启动电脑端 `文件互传.py`。
3. 手机上点击【广播搜索】或【扫描子网】，电脑端应出现在“在线设备”列表中。
4. 也可以在电脑端点击【自动搜索】/【手动添加】，输入手机 IP。
5. 手机端选择设备 → 添加文件/文件夹 → 点击【极速发送】。

### 存储位置

- 接收文件默认保存到应用外部私有目录 `Android/data/com.p2p.filetransfer/files/Received/`。
- 发送文件时，SAF 选择的内容会先复制到应用缓存目录 `cache/to_send/`，再传输。
- 续传状态保存在应用私有目录 `.p2p_resume/`，命名规则与桌面端一致。

### 已知限制

- 无零拷贝 `sendfile`（Android 无对应 API），全部走普通缓冲读写。
- UDP 广播在部分 ROM 被限，需优先使用“扫描子网”。
- 子网扫描仅支持 IPv4；IPv6 通过手动添加 + 心跳维持。
- 扫描并发 200（桌面端 1000），可在 `Constants.SCAN_CONCURRENCY` 调整。
- SAF 选择的内容会先复制到应用缓存再发送，可能额外占用缓存空间。
- 文件夹续传自动重发仅限单文件；文件夹续传需手动重新添加文件夹。

## 🔧 断点续传机制

### 单文件

1. **发送前协商**：发送方向接收方发送 `QUERY_OFFSET` 请求，询问对方已收字节数。
2. **取双方已确认的最小安全偏移量**：
   - 发送方记录（`~/.p2p_resume/resume_sender_*.json`）
   - 接收方记录（`~/.p2p_resume/resume_recv_*.json`）
   - 接收方在线协商返回的偏移量
3. **从偏移量继续传输**，接收方用已有数据初始化 SHA-256 哈希。
4. **完成校验**：比对整体哈希，一致即成功。

### 文件夹

- 双方交换 **清单（路径 + 大小 + mtime）**。
- 逐文件决策：`skip`（已存在）/ `resume`（续传）/ `full`（重传）。
- 每个文件独立续传状态文件（`folder_resume_*.json`）。

### 上线自动提醒

检测到有续传记录的目标设备上线时，会弹窗询问是否继续上传。

## 🗜️ 压缩策略

- **仅对文本文件自动压缩**（按扩展名判断）：`.txt / .log / .json / .py / .js / .html / .css / .csv / .yaml / .md / .sh` 等。
- 压缩等级 `6`（速度与比率平衡）。
- **压缩文件不支持续传**（压缩流无法分块恢复），续传时自动放弃压缩全量重传。

## 🛠️ 常见问题

### 1. 找不到设备？
- 双方需在同一网段或异地组网互通。
- 检查防火墙是否放行 UDP `9997/9998`、TCP `9999`。
- 尝试「手动添加」对方 IP。
- 部分路由器关闭了广播 → 改用「手动添加」。

### 2. 传输中断后如何恢复？
- 无需手动操作，**双方设备重新上线时自动弹窗提示续传**。
- 或重新拖入同一文件发送，程序会自动从断点继续。

### 3. 大网段（如 10.x.x.x）扫描慢？
- 已自动将 `10.x.x.x` 按 `/24` 处理（避免扫描 1600 万 IP）。
- 可临时调整 `MAX_SCAN_IPS` 与 `SCAN_THREADS`。

### 4. 高延迟网络（异地组网）传输慢？
- 程序会根据速度自动调整缓冲区（最大 8MB）。
- Socket 缓冲区设为 16MB，并启用 TCP KeepAlive 防断线。
- 建议关闭其他占用带宽的应用。

### 5. 传输时设备列表不刷新？
- 传输中会**暂停广播、扫描、心跳**以避免干扰，属正常行为。
- 传输结束后自动恢复。

### 6. 接收文件被拒绝？
- 同名文件存在时会弹窗询问是否覆盖。
- 路径穿越 / 非法文件名会被安全过滤。

## 🕳️ 公网房间模式 · 打洞优化（P2）

房间模式在 UDP 打洞成功建立可靠通道（UDP-RTP）后，用以下机制辅助 TCP 打洞，显著提升成功率：

| 编号 | 机制 | 说明 |
|:---:|---|---|
| #1 | COMMIT 可靠化 + 版本协商 | SYNC_COMMIT 用绝对时刻 + commit_id，重传 3 次幂等；协议版本 `PROTO_VER=2`，旧端自动回退 v1 |
| #2 | 轮次确定性对齐 | 多轮重试由 `my_id < peer_id` 一方主导下发下一轮绝对时刻，另一端跟随 |
| #3 | 候选并行连接 | 所有候选地址 Barrier 对齐后同时 connect，谁先成功用谁 |
| #4 | UDP 端口预测 | `pub_tcp` 为空时，用 UDP 打洞得到的端口 ±2 预测 TCP 候选（同 NAT 端口池假设） |
| #6 | TCP 就绪信号 | 映射观测建立后广播 `TCP_READY`，对端立即发起打洞（无需等服务器 punch_go） |
| #8 | 失败即时通知 | 彻底失败后发 `PUNCH_FAIL`，对端停止空等回退 UDP |
| #9 | 自适应超时 | connect 超时按 SYNC RTT 动态调整（`clamp(RTT×4, 3s, 8s)`） |

> 协议细节：UDP-RTP 消息类型 4=SYNC_REQ / 5=SYNC_ACK / 6=SYNC_COMMIT / 7=PUNCH_ROUND / 8=TCP_READY / 9=PUNCH_FAIL。
> 全部经 UDP-RTP 通道**两端直连**，不经过服务器，**服务器无需重新部署**。

## 🧭 梯度冗余多路径调度（V16）

打洞成功后，同一 peer 维护多条路径，按角色分级、按需保活、可换路续传。

### 路径角色

| 角色 | 传数据 | 保活策略 | 职责 |
|---|:---:|---|---|
| **热备 hot** | 是 | 最积极（快速感知断线） | 承载传输 |
| **保守暖备 warm_safe** | 否 | 硬性钳制不超过协议安全上限 | 热备一断立即接管 |
| **宽松暖备 warm_loose** | 否 | 贪心探测到极致（省电） | 最后防线，验证后上位 |

### 保活：软性探测 + 硬性下限

- 成功则指数增长逼近 NAT 超时边界
- 失败则与已知成功值二分收敛
- **硬性下限**：不低于协议 floor（TCP 30s / UDP 15s）
- **保守暖备硬性钳制**：不超过协议安全上限（TCP 3600s / UDP 60s）

### 热备断裂 → 立即重建

热备失效 → 保守暖备上位 → 宽松暖备验证后升级 → 立即重建补足 → 跨路径重传未确认部分

### 连接池复用 + 空闲降频

- 传输结束**不关连接**，下次直接复用（无需重新打洞）
- 空闲越久保活越稀疏：小于60s 乘1；小于10min 乘4；小于1h 乘16；更久 乘64

### 换路续传

某通道发送失败时，自动换到另一条可用路径重发：

| 类型 | 续传机制 |
|---|---|
| **单文件** | 重新走 QUERY_OFFSET 协商，从断点继续 |
| **文件夹** | 重新握手，接收端按本地文件状态 skip/resume/full |

## 📜 版本历史

### V17（后台保活 + 打洞稳定性 + 版本单一来源）
- **版本单一来源**：安卓用 `BuildConfig.VERSION_NAME`（build.gradle.kts 为准）、电脑端 `APP_VERSION` 常量、服务器 `DEFAULTS["APP_VERSION"]`，改一处全局生效
- **新增**：**后台保活增强**（对抗国产 ROM 后台冻结）
  - 服务加 `stopWithTask="false"`（最近任务划卡不杀服务）
  - `onTaskRemoved` 用 AlarmManager 1 秒后重启服务
  - WakeLock / WifiLock 每 4 分钟自动续期（部分 ROM 会静默撤销）
  - 启动时自动弹【系统"忽略电池优化"权限弹窗】（仅首次，prefs 记录）
  - 右上角"后台保活设置"：按厂商跳转"应用启动管理"页（华为/小米/OPPO/vivo）
- **打洞**：入口加**靶子检查**——`pub_tcp` 与内网候选都为空时不打（无候选可连），先请求映射、仍无则放弃，等对端登记后重触发
- **信令**：映射观测连接**持续重试**（失败不放弃，间隔递增上限 3s），不再 3 次即止
- **服务器**：映射登记后**主动广播 `member_update`** 给同房间成员（消除"等对端再发 punch_req"的时序竞态）
- **服务器**：`did` 兜底复用 id（客户端崩溃重启丢 myId 时，同设备复用旧 id，不产生"离开+加入"抖动）
- **去重**：双连接去重（同时打开可能形成两条独立 TCP，按 `preferred` 标记只保留约定主连接：ID 大者出站 / ID 小者入站）
- **修复**：入站重复连接时的 fd 泄漏

### V16.1（房间密码）
- **版本号统一为 V16.1**（电脑端标题 / 安卓 versionName=16.1 / 文档）
