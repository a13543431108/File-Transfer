# File-Transfer
文件互传，File Transfer - LAN
# 全环境极速传输 V14.0

一个基于 Python 的局域网 / 异地组网 P2P 文件互传工具，支持**断点续传**、**IPv4/IPv6 双栈**、**多设备并发发送**、**文件夹递归传输**、**zlib 压缩**与**SHA-256 完整性校验**。

---

## ✨ 功能特性

| 功能 | 说明 |
|------|------|
| 🚀 **零拷贝传输** | 优先使用 `os.sendfile`，避免用户态内存拷贝 |
| 🔁 **断点续传** | 单文件 + 文件夹逐文件续传，双方上线自动提醒 |
| 🌐 **IPv4 / IPv6 双栈** | 广播 + 扫描 + TCP 传输全支持 |
| 🗂️ **文件夹递归传输** | 保留目录结构、修改时间、逐文件独立校验 |
| ⚡ **动态缓冲区** | 根据实时速度自动调整 256KB ~ 8MB |
| 🧵 **多线程并发发送** | 同时向多个设备发送，独立连接 |
| 🗜️ **zlib 压缩** | 仅文本类文件自动压缩，节省带宽 |
| ✅ **SHA-256 校验** | 传输完成逐文件校验，失败自动重试（最多 3 次） |
| 🔍 **智能设备发现** | UDP 广播 + 心跳 + 多端口扫描（探测与收发隔离） |
| 🛡️ **路径安全** | 拒绝路径穿越、非法文件名 |
| 💓 **心跳保活** | TCP KeepAlive + UDP 心跳，3 次失败判定离线 |
| 📝 **断点状态持久化** | 存于 `~/.p2p_resume/`，程序重启后可恢复 |

## 📦 环境要求

- **Python 3.7+**（推荐 3.9+）
- 依赖：全部使用标准库，**无需 pip 安装任何第三方包**
  - `socket`、`struct`、`threading`、`hashlib`、`json`、`zlib`、`tkinter`、`ipaddress` 等
- 操作系统：Windows / Linux / macOS
  - Windows 上使用 `os.startfile` 打开接收目录
  - Linux/macOS 需要系统安装 `python3-tk`

> 若缺少 `tkinter`，请安装：
> - Ubuntu/Debian：`sudo apt install python3-tk`
> - CentOS/RHEL：`sudo yum install python3-tkinter`
> - macOS：`brew install python-tk`

## 🚀 快速开始

```bash
# 直接运行
python 文件互传.py

# 或 Windows 双击运行
```

### 使用流程

1. **启动程序**：自动获取本机 IP、开启广播、启动 TCP 监听（端口 `9999`）。
2. **发现设备**：
   - 点击「自动搜索」→ 广播探测，最快（推荐）
   - 点击「手动添加」→ 输入对方 IP（支持 IPv6）
   - 开启「后台扫描」→ 每 20 秒自动刷新设备列表
3. **选择接收方**：在左侧设备列表中**按住 Ctrl / Shift 多选**。
4. **添加发送内容**：右侧「添加文件」/「添加文件夹」，可上移下移排序。
5. **点击「极速发送」**：向所有选中设备并发发送。

## 📡 端口说明

| 端口 | 协议 | 用途 |
|------|------|------|
| `9999` | TCP | 文件数据传输 |
| `9998` | UDP | 设备发现、广播、心跳 |
| `9997` | UDP | 主动扫描探测（与收发隔离，避免干扰传输） |

> ⚠️ 使用异地组网（ZeroTier / Tailscale / WireGuard）时，确保上述端口未被防火墙拦截。

## 🔧 断点续传机制

### 单文件

1. **发送前协商**：发送方向接收方发送 `QUERY_OFFSET` 请求，询问对方已收字节数。
2. **取双方已确认的最小安全偏移量**：
   - 发送方记录（`~/.p2p_resume/resume_sender_*.json`）
   - 接收方记录（`~/.p2p_resume/resume_recv_*.json`）
   - 接收方在线协商返回的偏移量
3. **从偏移量继续传输**，接收方用已有数据初始化 SHA-256 哈希。
4. **完成校验**：比对整体哈希，一致即成功。

### 文件夹

- 双方交换 **清单（路径 + 大小 + mtime）**。
- 逐文件决策：`skip`（已存在）/ `resume`（续传）/ `full`（重传）。
- 每个文件独立续传状态文件（`folder_resume_*.json`）。

### 上线自动提醒

检测到有续传记录的目标设备上线时，会弹窗询问是否继续上传。

## 🗜️ 压缩策略

- **仅对文本文件自动压缩**（按扩展名判断）：`.txt / .log / .json / .py / .js / .html / .css / .csv / .yaml / .md / .sh` 等。
- 压缩等级 `6`（速度与比率平衡）。
- **压缩文件不支持续传**（压缩流无法分块恢复），续传时自动放弃压缩全量重传。

## ⚙️ 主要配置项

程序顶部可调整：

```python
UDP_PORT = 9998                 # 设备发现端口
TCP_PORT = 9999                 # 文件传输端口
SCAN_PORT = 9997                # 扫描探测端口
BUFFER_SIZE = 1 * 1024 * 1024   # 初始缓冲区（动态调整）
MAX_BUFFER_SIZE = 8 * 1024 * 1024
SOCKET_BUFFER_SIZE = 16 * 1024 * 1024
NODE_TIMEOUT = 600              # 节点超时（秒）
AUTO_SCAN_INTERVAL = 20         # 后台扫描间隔
SCAN_TIMEOUT = 0.5              # 单 IP 扫描超时
SCAN_THREADS = 1000             # 扫描并发线程数
MAX_SCAN_IPS = 65536            # 单次扫描最大 IP 数
```

## 🛠️ 常见问题

### 1. 找不到设备？
- 双方需在同一网段或异地组网互通。
- 检查防火墙是否放行 UDP `9997/9998`、TCP `9999`。
- 尝试「手动添加」对方 IP。
- 部分路由器关闭了广播 → 改用「手动添加」。

### 2. 传输中断后如何恢复？
- 无需手动操作，**双方设备重新上线时自动弹窗提示续传**。
- 或重新拖入同一文件发送，程序会自动从断点继续。

### 3. 大网段（如 10.x.x.x）扫描慢？
- 已自动将 `10.x.x.x` 按 `/24` 处理（避免扫描 1600 万 IP）。
- 可临时调整 `MAX_SCAN_IPS` 与 `SCAN_THREADS`。

### 4. 高延迟网络（异地组网）传输慢？
- 程序会根据速度自动调整缓冲区（最大 8MB）。
- Socket 缓冲区设为 16MB，并启用 TCP KeepAlive 防断线。
- 建议关闭其他占用带宽的应用。

### 5. 传输时设备列表不刷新？
- 传输中会**暂停广播、扫描、心跳**以避免干扰，属正常行为。
- 传输结束后自动恢复。

### 6. 接收文件被拒绝？
- 同名文件存在时会弹窗询问是否覆盖。
- 路径穿越 / 非法文件名会被安全过滤。
