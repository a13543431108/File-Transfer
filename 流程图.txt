#	流程图	内容
一	整体架构图	三端 + 服务器关系、数据流
二	局域网模式流程	广播/扫描发现 + TCP 直连
三	公网房间模式 · 总流程	完整时序（join→交换地址→打洞→传文件）
四	加入房间流程	地址解析→join→映射连接→发起打洞
五	TCP 打洞流程	候选地址→同时连接→重试→长连接
六	文件传输流程	续传协商→文件头→数据→校验
七	校验失败纠正流程	删文件+清状态+重传
八	服务器崩溃自愈 + 房间持久化	启动器循环 + 状态保存/恢复
九	信令服务器状态机	join/hb/punch_req/bye 的状态转换
十	客户端房间连接状态机	IDLE→JOINING→CONNECTING→CONNECTED

二、局域网模式流程
================================================================================

   [启动]
     │
     ├─► 获取本机 IP / 广播地址
     ├─► 启动 UDP 监听 9998（设备发现）
     ├─► 启动 UDP 监听 9997（扫描探测）
     ├─► 启动 TCP 监听 9999（文件传输）
     └─► 启动后台扫描（每 20s）
             │
             ▼
   ┌─────────────────┐      UDP 广播/扫描      ┌─────────────────┐
   │   设备 A         │◄──────────────────────►│   设备 B         │
   └────────┬────────┘                          └────────┬────────┘
            │                                            │
            ▼                                            ▼
      发现对方 → 加入设备列表                    发现对方 → 加入设备列表
            │                                            │
            └──────────────► TCP 直连 9999 ◄─────────────┘
                                  │
                                  ▼
                          发送 / 接收文件
                    （断点续传 / 压缩 / SHA-256）

四、加入房间流程（客户端）
================================================================================

   [用户输入 服务器地址 + 房间号，点"加入房间"]
              │
              ▼
   ┌──────────────────────────┐
   │ 解析服务器地址            │
   │ 支持：host / host:port /  │
   │      [ipv6]:port / 纯IPv6 │
   └────────────┬─────────────┘
                │
                ▼
   ┌──────────────────────────┐
   │ 建 UDP socket             │
   │ (v4/v6 按服务器地址族)    │
   └────────────┬─────────────┘
                │
                ▼
   ┌──────────────────────────┐
   │ 发送 join                 │
   │ (房间号/名字/tcp/内网IP/did)│
   └────────────┬─────────────┘
                │
                ▼
   ┌──────────────────────────┐   超时(10s)   ┌──────────────┐
   │ 等待 joined               │──────────────►│ 重试 join     │
   └────────────┬─────────────┘               └──────────────┘
                │ 收到 joined
                ▼
   ┌──────────────────────────┐
   │ 建 TCP 映射观测连接        │
   │ bind(打洞端口) → connect  │
   │ (服务器 3337) → 发 [len][id]│
   │ 保持打开                   │
   └────────────┬─────────────┘
                │
                ▼
   ┌──────────────────────────┐
   │ 等 200ms（服务器登记映射） │
   └────────────┬─────────────┘
                │
                ▼
   ┌──────────────────────────┐
   │ 对房间现有成员发起打洞请求 │
   │ (逐个 punch_req)          │
   └────────────┬─────────────┘
                │
                ▼
   ┌──────────────────────────┐
   │ 启动收包线程 + 心跳线程    │
   │ (心跳每 20s)              │
   └──────────────────────────┘

   ※ 连不上时：明确报错（提示填局域网 IP），不显示"已加入"

五、TCP 打洞流程
================================================================================

   收到 punch_go(对端 pub_tcp + 统一 at 时刻)
              │
              ▼
   ┌──────────────────────────┐
   │ 等到 at 时刻（双方同时开打）│
   └────────────┬─────────────┘
                │
                ▼
   ┌──────────────────────────┐
   │ 构造候选地址（按优先级）：  │
   │  1) 内网地址(v4/v6) + 对端TCP端口│
   │  2) TCP 公网映射 (pub_tcp)  │
   └────────────┬─────────────┘
                │
                ▼
   ┌──────────────────────────┐
   │ 逐个候选尝试 connect：     │
   │  · bind(本地 9999)         │
   │  · connect 对端 (超时 300ms)│
   └────────────┬─────────────┘
                │
        ┌───────┴────────┐
        │ 成功            │ 失败
        ▼                ▼
   ┌─────────┐    ┌──────────────┐
   │得到长连接│    │ 退避重试       │
   │ 保持打开 │    │ 2/4/8 秒       │
   └────┬────┘    │ 最多 3 次      │
        │         └──────┬───────┘
        │                │ 全失败
        │                ▼
        │         ┌──────────────┐
        │         │ 标记 FAILED   │
        │         │ 提示用户       │
        │         └──────────────┘
        ▼
   ┌──────────────────────────┐
   │ 启动接收循环              │
   │ 用 io_lock 串行化收发      │
   └──────────────────────────┘

   并发控制：Semaphore(6) 限制同时打洞任务数

六、文件传输流程
================================================================================

   [发送方]                                  [接收方]
     │                                          │
     │──① QUERY_OFFSET (续传查询)──────────────►│
     │◄─② 已收字节数 (8B)──────────────────────│
     │                                          │
     │ 计算偏移量（双方续传状态 + 远程）           │
     │                                          │
     │──③ 文件头 (flag/名字/flags/size/offset)─►│
     │◄─④ "OK" / "NO" ─────────────────────────│
     │                                          │
     │──⑤ 文件数据（可 zlib 压缩）─────────────►│ 边收边写盘
     │                                          │ 实时计算 SHA-256
     │──⑥ SHA-256 哈希 (64B hex)──────────────►│
     │                                          │ 比对哈希
     │◄─⑦ "MATCH" / "MISMATCH" ────────────────│
     │                                          │
     ▼                                          ▼
  成功→删续传状态                           成功→发布到目标目录

   动态缓冲：
     发送端：按实测速度调块大小（256KB~8MB）
     接收端：按实测速度调读缓冲（只增不减）

七、断点续传 / 校验失败纠正流程
================================================================================

   ┌──────────────────────────────────────────────────────┐
   │  校验失败 (MISMATCH) 处理 —— 自动纠正，不反复失败       │
   └──────────────────────────────────────────────────────┘

   [接收方收到 MISMATCH]                    [发送方收到 MISMATCH]
        │                                        │
        ▼                                        ▼
   ┌─────────────┐                          ┌─────────────┐
   │ 删除损坏文件 │                          │ 清除双方     │
   │ 删除续传状态 │                          │ 续传状态     │
   └──────┬──────┘                          └──────┬──────┘
          │                                        │
          │                                        ▼
          │                                  ┌─────────────┐
          │                                  │ 抛异常       │
          │                                  │ 触发上层重传 │
          │                                  └──────┬──────┘
          │                                        │
          │                                        ▼
          │                                  ┌─────────────┐
          │                                  │ 下次从头传   │
          │                                  │（无残留状态）│
          └──────────────────────────────────┴─────────────┘

   根因：同名文件残留时，续传协商仅凭"大小"判断会误续传。
   对策：失败即清理，保证重传从头开始。

八、服务器崩溃自愈 + 房间持久化流程
================================================================================

   [启动器 启动.py]
        │
        ▼
   ┌──────────────────────────┐
   │ 循环：启动 信令服务器.py    │
   └────────────┬─────────────┘
                │
                ▼
   ┌──────────────────────────┐
   │ 服务器运行中               │
   │  · 每 5s 保存房间状态      │
   │    → server_state.json    │
   │  · 加入/离开时立即保存      │
   └────────────┬─────────────┘
                │
        ┌───────┴────────┐
        │ 正常退出        │ 崩溃（异常退出）

        ▼                ▼
   ┌─────────┐    ┌──────────────┐
   │ 启动器退出│    │ 等 3s 自动重启 │
   └─────────┘    └──────┬───────┘
                         │
                         ▼
                  ┌──────────────┐
                  │ 重启时：       │
                  │ 读取 server_state.json│
                  │ 恢复房间成员表 │
                  │ 重置心跳时间   │
                  │ (客户端重新心跳)│
                  └──────────────┘

   配置：--no-restart 关闭自愈；--restart-delay N 调整等待秒数

九、信令服务器状态机
================================================================================

   全局状态：rooms / id_index / tcp_mappings / tcp_socks（受 state_lock 保护）

   ┌────────────┐   join    ┌──────────────────────────────────┐
   │   空闲      │──────────►│ 校验房间号                        │
   └────────────┘           │  · 房间满 → 回 ROOM_FULL          │
                            │  · 新建/加入房间                  │
                            │  · 登记成员（pub=来源地址）        │
                            │  · 回 joined + 广播 member_join   │
                            │  · save_state()                   │
                            └──────────────┬───────────────────┘
                                           │
              ┌────────────────────────────┼────────────────────────────┐
              │ hb                          │ punch_req                  │ bye / 超时
              ▼                             ▼                            ▼
   ┌──────────────────┐         ┌──────────────────────┐     ┌──────────────────┐
   │ 刷新 last_hb      │         │ 校验双方同房间         │     │ remove_member     │
   │ 更新 pub          │         │ 下发 punch_go 给双方   │     │  · 移除成员        │
   └──────────────────┘         │ (统一 at 时刻)         │     │  · 关闭TCP映射连接 │
                                └──────────────────────┘     │  · 广播 member_leave│
                                                             │  · save_state()    │
                                                             └──────────────────┘

   TCP 观测：客户端连 3337 → _handle_tcp_reg 读 [len][id] → 登记 tcp_mappings
             保持连接打开（维持 NAT 映射）
